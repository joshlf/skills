# Contributing

Public issues and pull requests are welcome for public-safe problems and proposed
changes. Describe the affected package, desired behavior, reproduction, and limits
of your evidence. Do not include private task data, credentials, or unpublished
third-party material. A repository URL does not authorize disclosure.

Maintainers import proposed changes into their canonical development workflow,
retain contributor attribution, and evaluate and accept the result there. They
then publish a generated release PR with the approved complete distribution.
The original contribution PR may be closed with a link to that release rather
than merged directly. This keeps source selection and supporting documentation
consistent. Documentation corrections follow the same route.

Proposed scripts and workflows are treated as untrusted code. They are not run
with publication credentials or private fixtures. Public tests use public inputs;
passing them does not approve disclosure or establish behavioral effectiveness.
Include applicable attribution and identify material AI-authored contributions.
