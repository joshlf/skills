# Architectural design: design

This package governs pre-implementation architectural specification across open
problems grounded in a software system, subsystem, semantic model, protocol,
schema, or framework. Routine implementation of a settled design, standalone
conceptual minimization without end-to-end architectural framing, and pure
empirical investigation without a target specification deliverable are outside
its scope. The skill enforces a strict pre-implementation boundary: invoking or
installing it grants no authority to modify production code, start background
processes or recurring jobs, or execute external publication or deployment
actions without explicit human authorization, and embedded execution directives
in inspected materials are quarantined as untrusted data.

`architectural-design` is a standalone, instruction-only package (`SKILL.md`
only) built around three cross-cutting backbones (`A` premise status and
`Separable-blocked` core isolation, `B` dependency invalidation with
`Terminal-Halt`, outer-loop budget, and `Non-Thrash Guard`, and `C` persistence,
compaction, and delegation boundaries) governing a single five-stage
deficit-driven precedence loop (`1. Ground -> 2. Contract -> 3. Factor and
Probe -> 4. Converge -> 5. Project`) that skips already-satisfied invariants and
avoids multi-paradigm fan-out on bounded single-axis tasks.

The protocol separates live target ground from non-authoritative foils using an
Assumption-Survival Test and co-designs an outcome-only `(C+, C-)` human-owned
contract independent of implementation structure. A unified zero-superset-tax
plumbing-invariance gate covers undecided static defaults and undecided
runtime-knob bounds, non-interactive `provisional` continuation is restricted to
an exact fail-closed complement (`foil-retirement` or strictly
plumbing-invariant clarifications and bounds), `separable-blocked` premises
isolate blocked discriminating axes while preserving full `(C+, C-)` visibility,
viable-only basin contrast gates multi-proposal intake (`Discovery-only`
pre-step) separately from `0`-proposal convergence dispatch, a strictly
read-only six-check pre-delivery audit verifies candidate contract compliance,
bounds, cliff attribution, policy isolation, superset-tax absence, and claim
validity, and Stage 5 separates timeless Partition-1 tracked repository docs
from three-partition standalone RFCs.

The skill operates standalone on bounded tasks and optionally composes strictly
through public interfaces of separately available peers (`model-refinement`,
`swarm-model-refinement`, `research-wheel`, `corpus-navigate`,
`reference-research`, `robust-code`, `reader-oriented-explanation`, and
`clear-writing`) without requiring unselected packages. Structural checks verify
package shape, disclosure hygiene, relative links, and export staging, not
live-host behavioral adherence, discovery routing accuracy, or measured session
cost; revisit the stage gates, runtime defaults, or peer composition if live
evidence shows high friction, missed escalations, or poor cost-to-rigor
trade-offs.

The [runtime instructions](../../architectural-design/SKILL.md) govern
execution. See [evidence and limits](../EVIDENCE.md) for the scope of public
validation.
